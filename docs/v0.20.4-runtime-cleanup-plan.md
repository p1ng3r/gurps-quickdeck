# GURPS QuickDeck v0.20.4 Runtime Cleanup Plan

## Goal

Reduce repeated rendering, duplicated state, unnecessary startup work, and release-package bloat without changing the three-panel UI2 command-desk layout or replacing the current Foundry Application V1 shell during this cleanup line.

## Phase 1 — Safe runtime cleanup

Status: implemented on `codex/v0.20.4-runtime-cleanup-phase1`.

- Remove the second overlay render from `openQuickDeck()`.
- Keep the hidden Foundry host template on an empty data object and build the full overlay view model once per render.
- Replace the obsolete pending-damage shadow state with one native GURPS-compatible payload queue.
- Avoid a full QuickDeck rerender after a damage roll when only the floating pending-damage popup changes.
- Use Foundry 13/14's `renderChatMessageHTML` hook and capture native damage only for the GM client.
- Lazy-load the developer art tuner only when a developer action is used.
- Replace stale pre-1.0 UI build labels with the installed module version.

Validation:

- `node --check scripts/main.js`
- `node --check scripts/quickdeck-app.js`
- Headless smoke test for host data, overlay view-model construction, and pending-damage payload creation.
- `git diff --check` equivalent whitespace validation.
- Manual Foundry 13 and 14 smoke testing remains required before changing the manifest's verified generation.

## Phase 2 — Render and observer efficiency

Status: implemented on `codex/v0.20.4-runtime-cleanup-phase2`; manual Foundry validation pending.

- Add a single render scheduler that coalesces direct UI refresh requests as well as document-hook refreshes.
- Split the overlay into roster, cockpit, actions, and popup render regions while preserving the current Handlebars data/action contracts.
- Keep the custom scrollbar manager alive for the overlay lifetime and refresh only affected hosts.
- Replace per-roll focus hook/timer creation with one persistent native-window focus controller.
- Add development timing counters for view-model construction, template rendering, DOM/listener work, and total render duration.

Implementation notes:

- The visible overlay is composed from four region templates while retaining the original `data-action` contract and direct-child layout structure.
- Existing `render(false)` calls now enter the central scheduler; high-frequency drawer, carousel, favorites, settings, item, combat, and modifier-bucket paths request narrower regions.
- Region replacement preserves drawer/carousel scroll offsets and restores focus to the matching action control when possible.
- The scrollbar manager retains one window listener and `ResizeObserver`; region changes explicitly release and rescan affected hosts.
- Native-window focus uses persistent `renderApplicationV1` and `renderApplicationV2` listeners rather than installing three listeners for every roll.

Exit criteria:

- Drawer, favorite, carousel, and search actions do not rebuild unaffected regions.
- Repeated actor/item/combat updates in the same frame produce one refresh.
- Native GURPS roll and damage windows still rise above QuickDeck reliably.

## Phase 3 — CSS and package cleanup

- Consolidate superseded CSS rules component by component using computed-style and screenshot comparisons.
- Remove verified-unused fonts and obsolete UI assets.
- Add a release allow-list so documentation, source art, local patches, and developer utilities are excluded from install ZIP files.
- Load reference-summary bundles by requested book instead of loading all books on the first reference lookup.
- Run Foundry 13/14 regression tests and update manifest compatibility only after successful testing.

Exit criteria:

- No visual movement of the left roster, center cockpit, right actions drawer, or collapse tabs.
- Release ZIP contains only runtime-required files.
- Reference fallback behavior remains unchanged.
